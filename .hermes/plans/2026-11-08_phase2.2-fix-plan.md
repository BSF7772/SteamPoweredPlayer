## 3. Rules for both workers
- Root cause first, with evidence (numbers, log lines); write the failing test, then the fix. Never weaken or skip a test.
- Prove on the **real library** (read-only, `SPP_REAL_LIBRARY`): `--realcheck` and `--uicheck` get new cases for every item
  (P1: loop length measured from mpv `time-pos` over ≥ 3 loops; P2: 10 consecutive frame-backs incl. across a chunk boundary;
  P3: every transport control's bounds inside the window at default and minimum size; L1: label/axis maths unit tests with a
  fixed "now"; L2: tiles appear for a growing synthetic session; and on a live real session when one is recording, otherwise SKIP).
- Trickplay sheet format: appending tiles to a live sheet must stay readable by the current reader; if the manifest format has to
  change, stop and report (ask-first).
- No personal data in the repo, commits or reports (paths, game names, ids, hardware). Window captures stay outside the repo.
- Budgets: `dotnet test` < 2 min, `--selftest` < 30 s, `--realcheck` < 60 s, `--uicheck` < 90 s.

## 4. Results (2026-11-08)
Run order changed to save time: W1 did P1-P3 (turn limit), then P4 (W1b) and W2 ran in parallel; all merged to `main`.
On merged `main`: `dotnet test` 769 pass; `--selftest` 27 PASS / 5 SKIP; `--uicheck` 26 PASS; `--realcheck` 28 PASS / 2 SKIP
(no live session at test time, no gap session). `--realcheck` took ~135 s instead of < 60 s while the GPU was busy with other
work; the maintainer attributes it to that, so it is not treated as a code issue.
- P1 root cause: mpv's `ab-loop` wraps with an internal seek inside the EDL (a revisited chunk, the known mpv defect), so every lap after the first was a fraction of A-B. The app now drives
  the loop itself (reload at A when B is reached). Measured lap error 4-47 ms over 3-4 laps (clip and cache, 1 and 2 chunks, 1x/2x).
- P2: frame back now lands on the previous frame's real pts, also across a chunk boundary (10/10 steps, worst 0.26 frame).
  The FF field counts with the nominal rate (59.09 fps snaps to 59.94), so each step changes FF by one; a truly missing frame
  in a VFR stream still skips one FF value.
- P3: the transport row collapses at narrow widths; window minimum 1100x700; `--uicheck` checks all 14 controls at default and minimum size.
- P4: `TimelineRuler.Layout` (pure, tested): nice-step ladder, labels about 80-200 px apart, frame labels at deep zoom; re-laid out
  only on zoom/scroll/resize.
- L1: the cache strip ends at now; the last 24 h use the right 75 %, older content is in the left 25 % behind a break; blocks
  show start (Today / Yesterday / weekday + date) and age. Not yet seen with a session older than 24 h.
- L2 root cause: `TrickplayQueue` skipped every live session, so nothing had a manifest while Steam recorded. Live sessions are
  now built incrementally, leaving out the newest (still open) chunk: tile latency ~65-125 ms, ~65-99 ms CPU per tile, 0 dropped
  frames while playing. Playlist thumbnails retry on `DerivedChanged`; markers reload when a `timelines/` file changes. Steam
  wrote the timeline of a finished ~80 s session once, at the end, with no entries; rewrites during a long recording are unobserved.
  Real live numbers come from `--realcheck` (`trickplay.live`) the next time Steam is recording.

## 5. Re-test of Phase 2.2 and fixes (2026-11-08)
- **Resize crash:** reproduced by the new `resize-stress` uicheck case (window width swept while a long cache session plays): 0xC000027B in 4 of 5
  runs; WER showed RO_E_CLOSED. Tiles were `SoftwareBitmapSource`s, which depend on an external bitmap; they are now `WriteableBitmap`s, which own
  their pixels: 0 of 8 runs, then clean in every full `--uicheck`. Whether eviction or something else closed the bitmap was not isolated.
- **Frame back:** the recording of the failure shows FF past 60 and a changing duration field, so the rate used for the timecode and the step changed
  between reloads. mpv's `container-fps` is not stable (59.09/60/55.82/46.92/58.89 measured on one clip); the session in the recording behaved as about 120
  although its chunks hold 178-180 frames per 3 s. The rate now comes from the chunks (`ChunkFrameRate`). One probe timeout also no longer disables exact
  steps for the whole recording (3 in a row do). New checks: 6 presses without waiting (`--realcheck`), the real button and displayed timecode (`--uicheck`).
- **A-B:** a seek decides: inside A-B the loop is active, outside it (either side) playback runs on, also through the zone, and the zone is drawn faded.
- **Cache strip markers:** moved to their own lane above the bar, away from the ruler; the lane takes no space without markers.
